# انتقال پیچا به Serverless — قدم‌به‌قدم

🟩 = سرور ربات (هلند، `176.65.151.206`)  ·  🟥 = سرور PasarGuard (آلمان، `168.222.43.253`)

ربات جدید (همه‌ی کد به JavaScript) روی همان پروژه‌ی Serverless‌ی که الان @pichanet_bot را به سرور PHP می‌رساند می‌نشیند.
**سه حالت دارد و با یک دستور عوض می‌شود** (فقط ادمین‌های «مدیر کل»، داخل چت خود ربات):

| حالت | چه کسی جواب می‌دهد |
|---|---|
| `relay` | ربات PHP روی سرور هلند (مثل الان) |
| `maint` | هیچ‌کس؛ به مشتری «در حال به‌روزرسانی» می‌گوید (فقط موقع کپی آخر داده) |
| `native` | ربات جدید روی Serverless |

بعد از `push` اول، ربات در حالت `relay` می‌ماند؛ یعنی **برای مشتری هیچ چیز عوض نمی‌شود** تا خودتان `/mode native` بزنید.
سرور هلند تا آخر روشن می‌ماند. برگشت: `/mode relay` (توضیح محدودیتش پایین‌تر است).

---

## فاز ۱ — آماده‌سازی (هر وقت؛ روی مشتری اثری ندارد)

### ۱.۱ آخرین کد روی سرور ربات 🟩
همان روش همیشگی deploy (ترجیحاً ساعت کم‌ترافیک، نه شب):
```
cd /var/www/html/mirzaprobotconfig && bash scripts/deploy.sh
```

### ۱.۲ لینک اشتراک «خود پنل» برای خریدهای جدید 🟩
```
cd /var/www/html/mirzaprobotconfig && php scripts/sub_mode.php native
```
لینک‌های قبلیِ `https://دامنه/sub/<سفارش>` را در فاز ۴ با ریدایرکت Apache روی سرور PasarGuard زنده نگه می‌داریم.

### ۱.۳ رله‌ی پرداخت روی سرور PasarGuard 🟥
یک رکورد DNS بسازید: `pay.theownlypwcha.top` → `168.222.43.253` (کلودفلر: ابر **خاکستری**، DNS only).
بعد از 🟩 پوشه را به 🟥 بفرستید و نصب کنید:
```
scp -r /var/www/html/mirzaprobotconfig/pasarguard/pay_relay root@168.222.43.253:/root/
```
🟥:
```
bash /root/pay_relay/install.sh pay.theownlypwcha.top
```
اگر Variza سرور خارجی را رد می‌کند، آی‌پی سرور ایران را هم بدهید: `bash /root/pay_relay/install.sh pay.theownlypwcha.top IRAN_IP`.
آخرش دستور `/setrelay https://pay.theownlypwcha.top KEY` و دو آدرس (وب‌هوک واریزا و SMS) چاپ می‌شود؛ **همین‌ها را نگه دارید**، فاز ۳ لازم می‌شود.
(آدرس‌های واریزا/SMS را الان عوض نکنید.)

### ۱.۴ پروژه‌ی Serverless را به‌روز کنید 🟩
```
cd /var/www/html/mirzaprobotconfig
php scripts/serverless_setup.php project --main --full
cd /root/picha-serverless-main
npm install
npx tgcloud push
npx tgcloud migrate
npx tgcloud webhook sync
```
`push` آدرس پنل مینی‌اپ را چاپ می‌کند: `https://appXXXX.tgcloud.ai/` — **کپی کنید**.
حالا ربات هنوز `relay` است و مثل قبل جواب می‌دهد. امتحان: از حساب مدیر کل در ربات بفرستید `/mode` ← باید «حالت ربات: relay» بیاید.

### ۱.۵ کپی «سرد» داده (جدول‌هایی که کم عوض می‌شوند) 🟩
```
cd /var/www/html/mirzaprobotconfig
php scripts/serverless_export.php --out=/root/picha-export
cd /root/picha-serverless-main
node tools/import.mjs /root/picha-export --cold
```
هر بار جدول‌ها را خالی و دوباره پر می‌کند. می‌توانید چند بار تکرار کنید.

### ۱.۶ آدرس پنل مینی‌اپ را به ربات بدهید
از حساب مدیر کل در ربات: `/setpanel https://appXXXX.tgcloud.ai`

## فاز ۲ — آزمایش بدون خطر (اختیاری ولی توصیه می‌شود)
روی یک ربات تست جدا (نه @pichanet_bot) همین پروژه را با حالت `native` اجرا کنید و خرید/تمدید/پنل را امتحان کنید؛
یا همین حالا کپی «گرم» (فاز ۳، بند ۳.۲) را بزنید و **فقط با `/mode native` چند دقیقه** تست کنید و برگردید `relay`.
(نتیجه‌ی تست‌های خودکار: ۱۴ سناریوی ربات ≈ ۳۷۰ پیام تلگرام یکسان با ربات PHP؛ پنل ≈ ۳۰۰ درخواست یکسان با API پنل PHP.)

---

## فاز ۳ — سوییچ (۱۰ تا ۱۵ دقیقه؛ ساعت کم‌ترافیک)

۱. **توقف کوتاه**: از حساب مدیر کل در ربات: `/mode maint`

۲. 🟩 کرون‌های PHP را متوقف کنید (ربات جدید خودش کار دوره‌ای را انجام می‌دهد):
```
systemctl stop cron
```

۳. **کپی «گرم»** (هرچه امروز عوض شده) 🟩:
```
cd /var/www/html/mirzaprobotconfig && php scripts/serverless_export.php --out=/root/picha-export
cd /root/picha-serverless-main && node tools/import.mjs /root/picha-export --hot
```

۴. رله‌ی پرداخت را وصل کنید (از حساب مدیر کل، همان دستوری که 🟥 چاپ کرد):
`/setrelay https://pay.theownlypwcha.top KEY`

۵. **سوییچ**: `/mode native`  ← اگر دیتابیس خالی باشد قبول نمی‌کند.

۶. بلافاصله در پنل واریزا: آدرس وب‌هوک را به همان آدرسی که 🟥 چاپ کرد بگذارید؛ و در برنامه‌ی SMS خوان بانک: آدرس را به رله.
(بین بند ۵ و ۶ هر پرداخت واریزا هنوز به سرور هلند می‌رسد؛ این فاصله را کوتاه نگه دارید.)

۷. ربات را امتحان کنید (کارهای زیر را خودتان با حساب‌تان بکنید):
   - `/start` از حساب مشتری؛ «سرویس‌های من»؛ کیف پول
   - خرید ارزان‌ترین پلن از کیف پول؛ تمدید
   - شارژ کارت‌به‌کارت با رسید ← تأیید از چت مدیر
   - پرداخت واریزا (مبلغ کم) ← بعد از «پرداخت کردم» خودکار تأیید می‌شود
   - `/webpanel` از حساب مدیر: پنل باز شود، «نمای کلی»، «سفارشات»، «پشتیبانی»، «مالی»
   - تیکت پشتیبانی از مشتری و پاسخ از پنل

### برگشت اضطراری
`/mode relay` (از چت مدیر) ← دوباره ربات PHP جواب می‌دهد. و 🟩 `systemctl start cron`.
⚠️ هرچه بعد از سوییچ روی ربات جدید ثبت شده (سفارش، شارژ) در دیتابیس سرور هلند نیست؛ بنابراین برگشت فقط در همان دقایق اول معنی دارد.
اگر مجبور شدید بعد از چند ساعت برگردید، همین جا بنویسید تا داده‌ی جدید را به MySQL برگردانیم.

## فاز ۴ — بعد از سوییچ (چند روز بعد، نه عجله)
- لینک‌های قدیمی `/sub/…` (در ریدایرکت Apache سرور PasarGuard): 🟩 `php scripts/sub_links_map.php` و بعد طبق `pasarguard/README.md` + `pasarguard/apache-sub-redirect.conf` (دامنه‌ی ربات را روی 🟥 ببرید).
- یک هفته سرور هلند را (بدون کرون) روشن نگه دارید؛ بعد خاموش کنید.
- فقط یک نسخه‌ی پشتیبان از آخرین دیتابیس MySQL نگه دارید (`scripts/picha-backup.sh`).

## چیزی که در ربات جدید «کم‌تر» از ربات PHP است
- منوی ادمین داخل چت فقط کارهای سریع را دارد (آمار، رسیدهای تأییدنشده، کارت کاربر، شارژ/کسر، درخواست حذف سرویس، `/config نام`, `/sendall`). بقیه‌ی مدیریت در **پنل مینی‌اپ** است (دکمه‌ی «🖥 پنل مدیریت (مینی‌اپ)»).
- درگاه‌های پرداختی که فقط داخل ربات PHP بودند و الان پشتیبانی نمی‌شوند: زرین‌پال، آقای پرداخت، plisio، ارز دیجیتال، ایران‌پی، **تترامینیتور** (تازه به ربات PHP اضافه شد؛ قبل از سوییچ باید به JS منتقل شود). فعال‌ها: کارت‌به‌کارت، واریزا، استارز تلگرام، کیف پول. (اگر از بقیه استفاده می‌کنید همین حالا بگویید.)
- ربات‌های نماینده‌ی جدا (botsaz) هنوز منتقل نشده.
- قرعه‌کشی امتیاز (`lottery`)، پایش آپتایم نودها/پنل‌ها، گزارش وضعیت سرور و هشدار سلامت درگاه (کرون‌های PHP) هنوز منتقل نشده؛ پایش را می‌شود از روی سرور PasarGuard یا یک سرویس بیرونی گرفت.
- فایل پیوست پشتیبانی در پنل مینی‌اپ به‌جای نمایش درون صفحه، به چت ربات خودتان فرستاده می‌شود.
