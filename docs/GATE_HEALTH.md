# بررسی اتصال درگاه‌ها (دکمه‌ای که کار نمی‌کند نشان داده نمی‌شود)

هدف: مشتری به درگاهی که وصل نیست پول نفرستد. هر درگاه **روشن** هر ۲ دقیقه بررسی می‌شود؛ اگر وصل نباشد دکمه‌اش از منوی پرداخت برداشته می‌شود و با وصل شدن خودکار برمی‌گردد.

## چه چیزی چک می‌شود
| درگاه | شرط وصل بودن |
|---|---|
| واریزا | رله پرداخت پاسخ بدهد (واریزا از طریق رله صدا زده می‌شود). بدون رله: آدرس API خودش |
| پی‌چی | رله پاسخ بدهد **و** آدرس پی‌چی پاسخ بدهد (تأیید پرداخت از رله برمی‌گردد) |
| پرداخت آنلاین (تتراِمیناتور) | API آن پاسخ بدهد |
| کارت به کارت | حداقل یک کارت با شمارهٔ کارت و نام ثبت باشد؛ وگرنه دکمه نیست |
«پاسخ» یعنی هر جوابی زیر ۵۰۰ (حتی ۴۰۱/۴۰۴)؛ فقط می‌پرسیم راه باز است یا نه، پس هیچ تراکنشی ساخته نمی‌شود.

## قاعده‌ها
- **دو بررسی ناموفق پشت‌سرهم** لازم است تا دکمه پنهان شود (یک تایم‌اوت اتفاقی نباید دکمه را بپراند).
- **اولین بررسی موفق** دکمه را برمی‌گرداند.
- اگر بررسی‌کننده متوقف شود (دادهٔ قدیمی‌تر از ۱۵ دقیقه)، درگاه **سالم** حساب می‌شود؛ هرگز بر پایهٔ خبر کهنه پنهان نمی‌کنیم.
- بدون داده (مثلاً بعد از دیپلوی)، همهٔ دکمه‌ها نشان داده می‌شوند.
- درگاهی که خاموش است بررسی نمی‌شود.
- **منوی قدیمی روی صفحهٔ مشتری:** اگر دکمهٔ یک درگاه را بزند که در این فاصله قطع شده، لینک ساخته نمی‌شود و منوی بقیهٔ روش‌ها را می‌گیرد (بدون مکث و بدون گزارش خطای تکراری).
- هر تغییر وضعیت (🔴 وصل نیست / 🟢 دوباره وصل شد) برای همهٔ ادمین‌ها می‌آید، یک بار.

## ادمین
`/gateways` برای هر درگاه وضعیت اتصال را نشان می‌دهد و دکمهٔ «🔄 بررسی اتصال همین حالا» دارد.

## فایل‌ها
`lib/gatehealth.js` (بررسی و کرون `gatehealth`) · `lib/gatepause.js` (`gatewayDownSet`) · `lib/catalog.js` (`stepPaymentKb`) · `lib/routes/pay.js` (محافظ کلیک) · `lib/admin/gateways.js` · تست `test/gatehealth_test.mjs`.

## مکث قدیمی هنوز هست
اگر هنگام ساخت لینک خطا برگردد (۵۰۰، قطع، کلید رد شده)، همان لحظه ۱۰ تا ۳۰ دقیقه پنهان می‌شود؛ بررسی دوره‌ای آن را **زودتر** و بدون نیاز به خطای مشتری می‌بیند.
